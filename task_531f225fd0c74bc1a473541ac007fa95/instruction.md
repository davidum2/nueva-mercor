I'm adding asynchronous approvals to Seata Saga, and I need workflows to suspend durably while waiting for external events. Within org.apache.seata.saga.statelang.domain, add StateType.WAIT with value "Wait" and a WaitState interface extending State. The required, non-blank Event is exposed through String getEvent(), optional Output through Map<String, Object> getOutput(), and optional Timeout and TimeoutNext through java.time.Duration getTimeout() and String getTimeoutNext(). Reject definitions unless Timeout and TimeoutNext are both present or both absent; supplied timeouts must be strictly positive ISO-8601 durations, including fractional seconds. Keep state-type lookup case-insensitive. For a Wait state, the set of possible subsequent destinations contains exactly its configured Next destination and, when present, its configured TimeoutNext destination, with no other destinations.

I need ExecutionStatus.WA to mean "Waiting". Entering a Wait must persist a WAIT state instance with status WA, suspend the machine with status WA and isRunning=false, and return without executing Next, setting a machine completion time, or reporting completion to the transaction coordinator. A fresh engine using the same database must be able to reload and resume the suspended workflow. The deprecated io.seata.saga.statelang.domain.StateType and ExecutionStatus wrappers in the compatible module need matching WAIT and WA constants, preserving wrap/unwrap round trips for every value.

Expose StateMachineInstance signal(String stateMachineInstanceId, String waitStateInstanceId, String event, Map<String, Object> payload) on StateMachineEngine. A matching event must atomically claim that exact activation, persist its status as SU and its output params as the payload, and synchronously continue until another suspension or a terminal state. Record a null payload as an empty map. Evaluate each Output expression against the recorded payload as its root and merge the mapped values into machine context without losing completed predecessors' outputs. Repeating the same event for an already satisfied activation must return the reloaded machine without repeating its continuation. In loops, a delayed duplicate targeting an older activation must not consume a newer activation of the same Wait state. Null or blank required arguments must throw EngineExecutionException with ParameterRequired or InvalidParameter; a nonexistent machine ID must report ObjectNotExists, and an event mismatch or an activation lost to timeout or compensation must report OperationDenied.

Also expose int fireDueTimeouts(java.time.Instant now) on StateMachineEngine. Claim persisted waits whose configured deadline is at or before now, persist each winner as SK, and continue along TimeoutNext. Return the number of claims won, leaving indefinite and not-yet-due waits suspended. This must work after engine reconstruction too. Reject null now with EngineExecutionException carrying InvalidParameter.

Signal delivery, timeout sweeps, and compensation must have a single winner per activation, including concurrent duplicate signals. A waiting child must suspend its enclosing SubStateMachine state and parent machine with WA. Completing or timing out the child must synchronously resume the parent, including through multiple nesting levels, with each level's output mappings applied. Compensating an ancestor must cancel active descendant waits before any completed predecessor is compensated, including waits in grandchildren.
