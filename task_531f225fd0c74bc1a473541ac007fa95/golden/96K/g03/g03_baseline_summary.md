## Objective
- Add a durable "Wait" state to Seata Saga (external-event approval with durable suspension/resume), spanning statelang domain/parser, engine, store, and compatible layers, with new `signal(...)` and `fireDueTimeouts(...)` APIs on `StateMachineEngine`, plus unit tests and build verification.

## Important Details
- Requirement spec (must all be satisfied):
  - Domain (`org.apache.seata.saga.statelang.domain`): `StateType.WAIT` value `"Wait"` (keep case-insensitive lookup); `ExecutionStatus.WA` value `"Waiting"` (existing values RU/SU/FA/UN/SK, `getStatusString()` exists); `WaitState extends State` with `getEvent()` (required non-blank), `getOutput()` (optional `Map<String,Object>`), `getTimeout()` (optional `java.time.Duration`), `getTimeoutNext()` (optional).
  - Parser: register `WaitStateParser` for "Wait" in `StateParserFactory`; reject definitions where only one of Timeout/TimeoutNext present; Timeout strictly positive ISO-8601 (plan: `java.time.Duration.parse`, supports fractional seconds); Event required non-blank.
  - Graph: `StateMachineUtils.getAllPossibleSubsequentStates` must return Wait's `Next` plus optional `TimeoutNext`.
  - Wait entry: persist WAIT state instance with status WA; persist machine with status WA and `isRunning=false`; return without executing Next; leave machine completion time unset; skip TC completion reporting.
  - Reload: a fresh engine on the same DB must reload a suspended workflow and resume it.
  - `StateMachineInstance signal(String stateMachineInstanceId, String waitStateInstanceId, String event, Map<String,Object> payload)` on `StateMachineEngine`: atomically claim the exact activation identified by `waitStateInstanceId` on matching event; winner persisted SU with payload as output params (null payload → empty map); continue synchronously to next suspension or terminal; evaluate Output expressions with recorded payload as root; merge mapped outputs into machine context preserving completed predecessors' outputs; replay on satisfied activation returns reloaded machine without re-running continuation; delayed duplicate for an older loop activation must not consume a newer activation of the same Wait state; null/blank required args → `EngineExecutionException` carrying `ParameterRequired`/`InvalidParameter`; nonexistent machine → `ObjectNotExists`; event mismatch → `OperationDenied`; activation lost to timeout/compensation → `OperationDenied`.
  - `int fireDueTimeouts(java.time.Instant now)` on `StateMachineEngine`: claim persisted waits with deadline <= now; winner persisted SK; resume along TimeoutNext; return number of claims won; indefinite waits and not-yet-due waits stay suspended; reconstructed engine discovers and resumes due waits; null `now` → `EngineExecutionException` carrying `InvalidParameter`.
  - Concurrency (single winner via atomic claim): duplicate matching signals; signal vs due timeout; signal vs compensation; timeout vs compensation.
  - Nesting: waiting child suspends enclosing `SubStateMachine` state in WA and its parent machine in WA; completing/timing out a child synchronously resumes parents through multiple nesting levels; apply each nesting level's output mappings during resumption.
  - Compensation: ancestor compensation cancels active descendant waits incl. grandchildren; cancellation precedes compensation of any completed predecessor.
  - Compatible wrappers (`io.seata.saga.statelang.domain`): add WAIT to deprecated `StateType`, WA to deprecated `ExecutionStatus`; preserve wrap/unwrap round trips for every value.
- Verified store facts:
  - Tables use `${TABLE_PREFIX}`: `state_machine_inst` and `state_inst`; both expose `status`; no schema change needed — deadline derived from persisted `gmt_started` + configured `Timeout`.
  - Machine columns: `id, machine_id, tenant_id, parent_id, business_key, gmt_started, gmt_end, status, compensation_status, is_running, gmt_updated, start_params, end_params, excep`.
  - State instance columns (row mapper, `DbAndReportTcStateLogStore` lines 1021–1043): `id, machine_inst_id, name, type, business_key, status, gmt_started, gmt_end, service_name, service_method, service_type, is_for_update, state_id_compensated_for, state_id_retried_for, input_params, output_params, excep`; type read via `StateType.getStateType(...)` (case-insensitive), status via `ExecutionStatus.valueOf(...)` (enum name) — new query SQL must match the insert encoding (still to verify in `recordStateStarted`).
- Engine mechanics discovered (from reads):
  - Event loop: `ProcessControllerImpl.process` → `businessProcessor.process(context)` (`CustomizeBusinessProcessor` → `StateMachineProcessHandler`) → `businessProcessor.route(context)` (`StateMachineProcessRouter`); sync publisher loops until instruction null.
  - `StateMachineProcessRouter.route` finally: `if (instruction == null && !stateInstruction.isEnd()) { EngineUtils.endStateMachine(context); }` — suspension design: `WaitStateHandler.process` does all persistence then sets `instruction.setEnd(true)`; `TaskStateRouter.route` returns null when `isEnd()` → bypasses `endStateMachine` (no gmtEnd, no TC report, no callback); loop/task pattern `if (Boolean.TRUE.equals(context.getVariable(DomainConstants.VAR_NAME_IS_LOOP_STATE))) return null` exists as precedent.
  - `ServiceTaskHandlerInterceptor.postProcess` early-returns when state instance null or `!stateMachineInstance.isRunning()` — natural skip once machine suspended; its `preProcess` creates/records state instances (`recordStateStarted` records RU before handler).
  - `ProcessCtrlStateMachineEngine`: `startInternal` builds context via `ProcessContextBuilder` (`org.apache.seata.saga.engine.utils`) and publishes to `processCtrlEventPublisher`; `compensateInternal` demonstrates reload + context rebuild + instruction + publish resume pattern and uses `recordStateMachineRestarted`; `reloadStateMachineInstance` + `replayContextVariables` replay each state's Output via `ParameterUtils.createOutputParams(resolver, state, output)` (casts `ServiceTaskStateImpl` — Wait needs handling); `clearUp` in finally cleans ThreadLocal (XID).
  - `StateInstruction` fields: `stateName, stateMachineName, tenantId, end` (+temporary state; `getState(context)` resolves temporaryState or by name); states hold `State.getStateMachine()` reference.
  - `parentId` format: parent machine instance id + `SEPERATOR_PARENT_ID` + parent state instance id (`EngineUtils.generateParentId`) — enables exact parent SUB_STATE_MACHINE activation lookup on child resume.
  - Interceptors attach via `@LoadLevel`/EnhancedServiceLoader on `InterceptableStateHandler`; plan: `WaitStateHandler` as plain `StateHandler` (no interceptors) creating the WAIT state instance inside `process()`, registered in `StateMachineProcessHandler`'s StateType→handler map.
  - `compensateInternal` only calls `checkStatus` when `compensationStatus != null` → compensating a suspended, never-compensated machine is allowed.
- Planned implementation design:
  - New SQLs in `StateLogStoreSqls`: claim CAS `UPDATE ${TABLE_PREFIX}state_inst SET status=?, output_params=?, gmt_updated=? WHERE machine_inst_id=? AND id=? AND status='WA'` (1 row = win); machine suspend `status='WA', is_running=false`; machine resume `status='RU', is_running=true` (`recordStateMachineRestarted` may only set is_running/gmt_updated — verify); query waits `SELECT ... WHERE type=? AND status='WA'` (or machine-status query — state-level query preferred since it finds waits globally incl. in child machines).
  - signal: reload machine (missing → ObjectNotExists), reload state instance, validate args, match event vs definition `Event` (mismatch → OperationDenied), CAS WA→SU with serialized payload; loser with SU → return reloaded machine (idempotent); loser otherwise → OperationDenied; winner: machine RU + running persisted, context = replayed vars + Output mappings with payload root, instruction = Wait's `Next`, publish sync; if machine reaches terminal and has parentId → recursively resume parent chain.
  - Parent resume: parse parentId → reload parent, find its WA SUB_STATE_MACHINE state instance by id, set status from child final status, outputParams via `ParameterUtils.createOutputParams(resolver, subState, child.getEndParams())`, `recordStateFinished`, continue parent from sub-state Next with replayed parent vars; recurse for grandparent when parent completes.
  - Timeout: query WA wait state instances, load machine + definition (`repo.getStateMachineById(machine.getMachineId()).getState(name)` → `WaitState.getTimeout()`; null → indefinite, skip), deadline = `gmtStarted` + timeout; if <= now → CAS claim → SK → resume along `TimeoutNext`; count claims won.
  - Compensation cancellation: recursive walk (WAIT & WA → CAS to SK; SUB_STATE_MACHINE & WA → recurse into child machines via `queryStateMachineInstanceByParentId(generateParentId(stateInstance))`), hooked before compensation stack processing (in/near `CompensationTriggerStateHandler`).
  - Planned `DomainConstants` addition: `OPERATION_NAME_SIGNAL` ("signal") for continuation contexts (name provisional).
  - SubStateMachineHandler must be modified: when child engine.start returns WA instance, set parent state instance WA, persist suspension, set end, return without routing to Next.
