Introduce `GSLC_INVALIDATE_RGN_MAX` as the maximum number of simultaneously-tracked active regions. It defaults to 8, and a user configuration header (one of the stock `configs/` files or a project's own) or a compiler define can set it to any value from 1 to 32. Add three net-new public query functions:
- `gslc_InvalidateRgnCount` takes the GUI context and returns a `uint8_t` count of active tracked regions, or 0 if invalidation is disabled.
- `gslc_InvalidateRgnGet` takes the GUI context, a rectangle array, and a `uint8_t` maximum count, writes the active regions sorted canonically (ascending by y, then x, then h, then w) into that array when it is non-null and up to that maximum, and returns the `uint8_t` total count of active tracked regions.
- `gslc_InvalidateRgnIsDirty` takes the GUI context and a test rectangle, and returns a `bool` reporting whether that rectangle has a positive-area intersection with at least one active region.

Refactor the existing region invalidation functions to maintain a set of at most `GSLC_INVALIDATE_RGN_MAX` pairwise non-overlapping regions with no dynamic memory allocation, neither when the set is updated or queried nor when it is redrawn and presented. Neither the core library nor its SDL driver calls an allocation function of the C library or the operating system anywhere in its own code today (the `malloc` family, memory mapping, or helpers such as `strdup` and `asprintf` that return allocated buffers), and that must stay true; what SDL does internally on their behalf, such as creating a surface or rendering text, is not part of this. The addition function clamps each input rectangle to the display bounds and drops any that come out empty or fall entirely offscreen. As elsewhere in the library, the right and bottom edges of a rectangle are assumed to fit in the signed 16-bit coordinate range. Any added rectangle with positive-area overlap must transitively coalesce with the existing active regions into their bounding-box union until every region is pairwise disjoint. Two areas invalidated in the course of a single element operation therefore remain separate active regions when they do not overlap.

If the region count exceeds `GSLC_INVALIDATE_RGN_MAX`, repeatedly merge the pair that minimizes wasted area (union area minus the two individual areas). Break ties independently of the order in which the regions were added: put the canonically smaller region of each pair first, then take the pair whose first region is canonically smallest, or whose second region is canonically smallest when the first regions are equal, comparing regions ascending by y, then x, then h, then w. Re-run transitive coalescing after each forced merge. The screen invalidation function yields exactly one region covering the full display, and the reset function empties the set and disables invalidation.

When invalidation is active, each active region must be drawn independently, with the clipping rectangle set to that region before its background and element rendering, so that nothing outside the active regions is repainted. On a partial redraw every element that is pending redraw must still end up rendered in each active region it intersects, including an element that reaches into more than one of them. To prevent full-screen flicker, the screen presentation step of the SDL1 display driver must update only the individual active regions, exactly one update per region, instead of refreshing the entire display, and this holds even when a single active region covers the whole display; with no active region it refreshes the whole display as before. Display drivers that can only present the whole display, such as SDL2, keep doing so. The active region set must remain fully populated during that presentation step, and must only be emptied after the redraw and presentation pass completes, at which point clipping is restored to the full display.
