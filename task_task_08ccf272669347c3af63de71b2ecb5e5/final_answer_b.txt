Implemented `ArtifactReferenceServiceProvider` following the repo's existing Angular provider-registry convention (matching `ServerGroupCommandRegistry`).

**New: `app/scripts/modules/core/src/artifact/artifactReference.service.ts`**

```ts
export class ArtifactReferenceServiceProvider implements IServiceProvider
```

Public API:
- `registerReference(stageType, fields: string | string[])` — declares artifact-reference field(s) for a stage type; accumulates across calls so multiple fields per type are supported.
- `getReferences(stageType): string[]` — returns a defensive copy.
- `removeReferenceFromStages(reference, stages)` — the sweep.
- `$get()` — provider hook, so it's injectable as `artifactReferenceService` and configurable from `config` blocks alongside `pipelineConfigProvider.registerStage`.

Fields are lodash-style paths, which covers all four required shapes with one syntax:

| Path | Behavior |
|---|---|
| `expectedArtifactId` | top-level property deleted |
| `cluster.imageSource.artifactId` | nested property deleted |
| `clusters[1].expectedArtifactId` | nested under an array index |
| `expectedArtifactIds[1]` | array element spliced (index shifts correctly) |
| `expectedArtifactIds` | every matching element filtered out |

Key implementation detail: `removeReferenceAtPath` resolves the *parent* container rather than the field itself (`artifactReference.service.ts:71-77`), which is what makes deletion/splicing possible. If any segment is unresolvable, or the value doesn't equal the reference, it returns early and the stage is untouched. Array parents get `splice` (so no `undefined` holes) while object parents get `delete`.
