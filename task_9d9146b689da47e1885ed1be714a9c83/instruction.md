The Python Pipeline DAG engine executes all operators (`Op`s) for every request. We want to implement per-request conditional branch execution to support dynamic routing within the DAG. Your working directory is `/app`. Run Python against the package from `/app` with `PYTHONPATH=python`; the `sitecustomize.py` in that directory supplies the Python 3.11 compatibility shims the package needs to import.

### Public API Extensions

The `pipeline.operator.Op` base class (and thus all user operators and `RequestOp`) gains the following methods:

- `route(self, output_data, data_id=0, log_id=0)`: A user-overridable hook invoked at most once per request. It receives that request's `data_id`. For standard `Op`s, it runs immediately after successful `postprocess` with the emitted dict in `output_data`. For `RequestOp`, it runs on the DAG entry path with `unpack_request_package`'s output dict in `output_data`. Returns `None` (default) to activate all successors, or any iterable of successor names to activate, including one that can only be consumed once such as a generator (empty = activate none). If any returned name is not in `self.get_succ_op_names()`, even alongside valid names, that request must fail with `err_no` set to `ChannelDataErrcode.INPUT_PARAMS_ERROR.value`, and a response must be delivered promptly; later requests are unaffected.
- `on_skipped(self, data_id=0, log_id=0)`: A user-overridable hook (default no-op returning `None`). Invoked exactly once, with that request's `data_id`, per request for which the `Op` is skipped. An exception raised inside it must not stall the DAG or change the request's response.
- `get_succ_op_names(self)`: Returns a `set` of `str` containing the names of the `Op`'s immediate successors in the established DAG topology (including the `@DAGExecutor` sink for the final output `Op`). Returns an empty `set` before the topology is established.
- `get_pred_op_names(self)`: Returns a `set` of `str` containing the names of the upstream producer `Op`s in the established topology. Returns an empty `set` before topology is known. The `RequestOp` is never reported as a predecessor, so an `Op` fed only by the `RequestOp` returns an empty `set`.

The `pipeline.error_catch.CustomExceptionCode` enum (re-exported as `pipeline.channel.ChannelDataErrcode`) gains a net-new member `SKIPPED = 3004`.

### Behavioral Invariants

- **Execution & Transitive Skipping**: An `Op` executes for a request iff at least one incoming edge is active; otherwise, it is skipped. Skipped `Op`s run none of `preprocess`/`process`/`postprocess`/`route` for that request, fire `on_skipped` exactly once, and propagate the skip downstream by deactivating all outgoing edges.
- **Partial Joins**: A join `Op` that executes receives, in the `input_dicts` argument to `preprocess`, only the entries of predecessors whose edge to it is active for that request. Nothing is provided, not even a placeholder or sentinel entry, for a predecessor that was skipped or that ran but did not select the join in its `route`.
- **Liveness & Concurrency**: Skipping must not block other `Op`s reading the same upstream output, hold back a join whose remaining predecessors ran, or leave the request unanswered. Routing is per-request: concurrent or auto-batched requests must be routed individually without mutual interference. Routing behaves the same whether `Op`s run as threads or as processes (`is_thread_op`).
- **Terminal Skips**: If routing leaves a request with no active path to the response, `DAGExecutor.call()` must return promptly with a `Response` whose `err_no` is set to `CustomExceptionCode.SKIPPED.value`. This applies wherever the last path is cut, whether by a single `route` call or by the combined decisions of several `Op`s, and includes the final output `Op` returning an iterable that omits `@DAGExecutor`.
- **Error Precedence**: Operator execution errors take precedence over routing. They propagate along all outgoing edges of the failing `Op`, every `Op` downstream passes the error on along all of its own outgoing edges without running, and `route` is not consulted for requests that already failed, including a request that `unpack_request_package` rejected with a product error code.
- **Topology Availability**: The successor and predecessor name sets must be populated as soon as `PipelineServer.set_response_op()` returns, without a `DAGExecutor` having been constructed or started.
- **Backward Compatibility**: If all `Op`s use the default `route` returning `None`, the DAG must run exactly as before.
- **Scope**: `Op`s constructed with `jump_to_ops` keep their current behavior; `route` does not need to be supported for them. The once-per-request guarantees of `route` and `on_skipped` cover a single pass of a request through the DAG: when the executor replays a request (`dag.retry` greater than 1), the hooks may run again for the replay.
