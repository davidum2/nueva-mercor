Druid's window function engine supports only positional row offsets (`WindowFrame.Rows`) and peer-group offsets (`WindowFrame.Groups`). Support native value-based `RANGE` window framing across the query engine, on-heap aggregation, value processors, and SQL planner/validator.

Implement a new native window frame type `WindowFrame.Range` as a public nested class in `WindowFrame`, registered as Jackson subtype `"range"`. It accepts `@Nullable Double lowerOffset`, `@Nullable Double upperOffset`, and a non-null `ColumnWithDirection orderBy`, exposed via `getLowerOffset()`, `getUpperOffset()`, and `getOrderBy()`. A null offset represents a positionally unbounded limit (`UNBOUNDED`), while a non-null offset is a signed distance in the ordering key's value space. Provide a static factory method `WindowFrame.range(@Nullable Double lowerOffset, @Nullable Double upperOffset, ColumnWithDirection orderBy)`. `WindowFrame.Range` is a standalone `WindowFrame` implementation (not extending `OffsetFrame`), overrides `equals` and `hashCode` by value, and supports Jackson serialization and deserialization.

Extend framed aggregation (`FramedOnHeapAggregatable#aggregateAll`) and value processors (`WindowFramedAggregateProcessor`, `WindowFirstProcessor`, `WindowLastProcessor`) to accept `WindowFrame.Range`. Frame resolution over sorted partitions must observe:
- For a non-null ordering key value `v` and finite offset `o`, the bound value is `v + o` when ordered ascending (`ASC`) and `v - o` when ordered descending (`DESC`), forming a closed interval `[lowerBound, upperBound]`.
- Unbounded bounds (`UNBOUNDED PRECEDING` / `UNBOUNDED FOLLOWING`) remain positional, extending to the partition boundaries and including rows with `NULL` ordering keys.
- When the current row's ordering key is `NULL`, finite-offset bounds resolve to the boundaries of the contiguous run of `NULL` ordering values containing that row (its peer group).
- Rows with equal ordering key values (peers) resolve to identical frame boundaries and receive identical output values.
- Empty frames emit the aggregator's zero-row default value, or `null` for `FIRST_VALUE` and `LAST_VALUE`.
- A `Range` frame covering the full partition for every row evaluates identically to `WindowFrame.unbounded()`.
- Resolution must support numeric ordering columns (`LONG`, `FLOAT`, `DOUBLE`, where timestamp columns reach the native engine as `LONG`) across all `RowsAndColumns` implementations. Ordering column types that do not support value arithmetic with finite offsets must throw an unchecked `DruidException`.

Update the SQL validator and Calcite window planning to accept offset-based `RANGE` window frames (`RANGE BETWEEN <offset> PRECEDING AND <offset> FOLLOWING`, including one-sided and `CURRENT ROW` variations) when the window has exactly one `ORDER BY` key. The ordering key may be numeric or a timestamp column; the bound literal may be a numeric magnitude or a day-time `INTERVAL`. Day-time `INTERVAL` offsets must map to their millisecond magnitude as a floating-point offset without integer truncation. Unsupported `RANGE` window forms (such as multiple `ORDER BY` keys or non-numeric/non-interval ordering keys with finite bounds) must fail validation or planning.
