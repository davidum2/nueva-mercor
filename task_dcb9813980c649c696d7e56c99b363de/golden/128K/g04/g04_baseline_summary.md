## Objective
- Add native value-based `RANGE` window framing to Druid in `/app`: a `WindowFrame.Range` type, native frame resolution for aggregation and value processors, SQL validator/planner wiring, plus tests; multi-key `RANGE` queries must still fail.

## Important Details
- `WindowFrame.Range` must be a public nested class of `WindowFrame`, registered as Jackson subtype `"range"`, implementing `WindowFrame` directly (not extending `OffsetFrame`, which uses `Integer` offsets).
- `Range` fields: `@Nullable Double lowerOffset`, `@Nullable Double upperOffset`, non-null `ColumnWithDirection orderBy` (no null-check on `orderBy`, EqualsVerifier consideration); getters `getLowerOffset()`, `getUpperOffset()`, `getOrderBy()`; factory `WindowFrame.range(@Nullable Double lowerOffset, @Nullable Double upperOffset, ColumnWithDirection orderBy)`; equals/hashCode by value; Jackson ser/deser. All implemented.
- Semantics: null offset = positionally unbounded side; non-null = signed distance in the key's value space; bound is `v + o` under `ASC`, `v - o` under `DESC`; frame = closed interval between bounds; unbounded sides reach partition edges and include `NULL`-key rows; when current key is `NULL`, finite bounds resolve to the edges of the contiguous `NULL` run; peers (equal keys) get identical bounds/output; empty frame → zero-row default / `null` for FIRST_VALUE/LAST_VALUE; whole-partition `Range` ≡ `WindowFrame.unbounded()`; `LONG`/`FLOAT`/`DOUBLE` keys work (timestamp arrives as `LONG`); non-numeric key with finite offset must throw unchecked `DruidException`; `Range` must work for every `RowsAndColumns` (only `DefaultFramedOnHeapAggregatable` implements `FramedOnHeapAggregatable`, so handling it + value processors covers all).
- `WindowFrame` maps `"rows"` → `Rows`, `"groups"` → `Groups`, `"range"` → `Range`; `unbounded()` returns `rows(null, null)`; classes nested in an interface are implicitly static (EqualsVerifier-compatible); `WindowFrame.forOrderBy(...)` also exists (used by `WindowOperatorQueryBuilder`).
- `ColumnWithDirection`: `getColumn()`, `getDirection()`, `Direction.getDirectionInt()` (ASC=1, DESC=-1), static `ascending(String)`/`descending(String)`, proper equals/hashCode.
- `RangeFrameResolver` (`org.apache.druid.query.operator.window`, created): ctor `(RowsAndColumns rac, WindowFrame.Range frame)`; peer groups via `ClusteredGroupPartitioner.fromRAC(rac).computeBoundaries(ImmutableList.of(orderColumn))`; keeps `groupBoundaries`/`frameStarts`/`frameEnds`; getNumGroups guards empty rac (`computeBoundaries` returns `new int[]{}` for 0 rows); null-run = leading nulls (ASC) / trailing nulls (DESC); `NULL` row → frameStart = `nullRunStart` (or 0 if lower unbounded), frameEnd = `nullRunEnd` (or numRows if upper unbounded); non-null row via binary searches over the non-null region only (`getDouble` on null row gives 0.0): ASC start = first row ≥ `v+lower`, ASC end = first row > `v+upper` (exclusive), DESC start = first row ≤ `v-lower`, DESC end = first row < `v-upper` (exclusive; equals null-run start when no non-null row qualifies); keys compared as `accessor.getDouble(row)` (precision loss beyond 2^53 accepted); missing column → `DruidException.defensive`; finite bound + `!accessor.getType().isNumeric()` → defensive `DruidException` (`TypeSignature.isNumeric()` default method; `RowSignature.getColumnType(int)` → `Optional<ColumnType>`); frame ends normalized `frameEnds = Math.max(frameStarts, frameEnds)` because `AggIntervalCursor.moveTo` breaks on inverted intervals.
- `moveTo` stays unchanged: Range bounds are monotone non-decreasing across groups, so branch 1 (same start, larger end) extends incrementally, branch 2 never fires, else full recompute — always correct.
- `DefaultFramedOnHeapAggregatable` (edited): `buildIteratorFor` Range branch → new `buildRangeIteratorFor(rac, rangeFrame)` yielding one `AggInterval` per peer group; `isEffectivelyUnbounded` checks Range (both offsets null) BEFORE the `OffsetFrame` unwrap (would otherwise NPE/misbehave). `WindowFramedAggregateProcessor.process` falls back to `new DefaultFramedOnHeapAggregatable(RowsAndColumns.expectAppendable(inputPartition))` when `as(FramedOnHeapAggregatable.class)` returns null.
- `WindowValueProcessorBase.computeFirstOrLastValueFramed` (edited): Range branch uses the resolver; value emitted only when `frameStart < frameEnd` — `getObject(frameStart)` for FIRST, `getObject(frameEnd - 1)` for LAST, assigned to rows `[groupStart, groupEnd)`; stale issue-15767 comment replaced with a GROUPS-vs-RANGE distinction note.
- `Windowing.java` (edited): `ColumnType` import added; `getWindowFrame()` emits `WindowFrame.range(...)` only when `isOffsetBound(lower)` or `isOffsetBound(upper)` (i.e. PRECEDING/FOLLOWING offset), keeps `groups(...)` for UNBOUNDED/CURRENT-ROW-only bounds (STRING keys with those bounds work today via `groups`); `buildRangeFrame()` requires exactly one `RelFieldCollation` key (else QueryException) and `sig.getColumnType(fieldIndex).orElse(null)` non-null + `isNumeric()` (timestamps are LONG via `Calcites.isLongType`), else QueryException with `SQL_QUERY_UNSUPPORTED_ERROR_CODE` (`"SQL query is unsupported"`); direction from `getOrdering().get(0).getDirection()`; `getBoundAsDouble` returns null (unbounded) / `0.0` (CURRENT ROW) / `±getConstantAsDouble` (negated when PRECEDING); `getConstantAsDouble` reads `((Number) window.constants.get(refIndex - sig.size()).getValue()).doubleValue()` — must NOT use `getBoundAsInteger` (intValue() overflows day-time interval millis); offsets reach `Windowing` as `RexInputRef` into `window.constants`.
- `DruidSqlValidator.validateWindow` (edited): the RANGE rejection now throws only when `orderList == null || orderList.size() != 1 || !isValidRangeBound(lowerBound) || !isValidRangeBound(upperBound)`; `isValidRangeBound` accepts UNBOUNDED/CURRENT ROW and PRECEDING/FOLLOWING literals that are `SqlNumericLiteral` or day-time `SqlIntervalLiteral` (year-month rejected; day-time maps to millis); message kept verbatim: `Order By with RANGE clause currently supports only UNBOUNDED or CURRENT ROW. Use ROWS clause instead.` (so `qaWin` multi-key cases keep failing and `qaWin` files stay as recorded; `!error` quidem checks squashed traces, expecting `QueryInterruptedException`).
- Key-type rejection (e.g. STRING key) happens at planning time, not validation, so a single-key STRING offset RANGE passes validation and throws QueryException during planning; how QueryException surfaces through `testBuilder().run()` is unverified — no existing test asserts `SQL_QUERY_UNSUPPORTED`; must determine empirically (likely `assertThrows(QueryException.class, ...)`).
- `ROW_NUMBER()` never calls `getWindowFrame()`, so single-key RANGE passes validation and planning → `testUnSupportedRangeBounds` (CalciteQueryTest ~line 15620) must switch to `ORDER BY dim1, dim2` while keeping the message and `(line [1], column [31])` (prefix `SELECT dim1,ROW_NUMBER() OVER (` unchanged).

- Test conventions: `WindowFrameTest` uses `EqualsVerifier.forClass(...).usingGetClass().verify()`; `WindowFirstProcessorTest`/`WindowLastProcessorTest` use `MapOfColumnsRowsAndColumns.fromMap(map)`, `new WindowFirstProcessor(input, output, frame)`, `new RowsAndColumnsHelper().expectColumn("out", ColumnType.STRING, ...)`, `WindowFrame.groups(0, 1, Collections.singletonList("grp"))`; `WindowFramedAggregateProcessorTest` uses `new WindowFramedAggregateProcessor(theFrame, theAggs)`, `proc.process(new NoAsRowsAndColumns(rac))`, `expectColumn(...).allColumnsRegistered().validate(...)`; CalciteQueryTest window tests start with `assumeFeatureAvailable(EngineFeature.WINDOW_FUNCTIONS)` (defined `BaseCalciteQueryTest` line 543); `RewriteFirstValueLastValueRule` does not interfere.
